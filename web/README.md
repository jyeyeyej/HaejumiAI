# 해주미 PC 웹 첫 버전

Windows PC의 브라우저에서 사용하는 React 화면입니다. 기존 Node.js 참조 백엔드와 같은 `/api/v1`을 사용하며, 서버가 프로젝트·작업·버전·승인의 단일 데이터 원천입니다. 브라우저가 직접 고른 사진·영상 최대 20개를 한 프로젝트에 업로드합니다. 선택 상한은 빌드 환경변수 `VITE_MAX_SELECTED_MEDIA`로 1~30개 사이에서 변경하며 서버 상한과 맞춰야 합니다.

## 실행

1. 프로젝트 루트 `.env`에 기존 서버 인증값을 설정하고 `npm start`로 백엔드를 127.0.0.1:8765에서 실행합니다.
2. `cd web` 후 `npm ci`, `npm run dev`를 실행하고 `http://127.0.0.1:5173`에 접속합니다.
3. `http://127.0.0.1:5173`에서 서버 Bearer 토큰을 한 번 입력합니다. 서버가 30일 유효한 HttpOnly·SameSite=Strict 로그인 쿠키를 발급합니다. 새로고침·브라우저 재실행·PC 재부팅 후에도 쿠키와 서버 세션이 유효하면 자동 연결됩니다. `localhost` 대신 항상 `127.0.0.1` 주소를 사용하세요.
4. 결과물 빌드는 `npm run build`, 로컬 빌드 미리보기는 `npm run preview` (`http://127.0.0.1:4173`)입니다.

Vite 개발·미리보기 서버는 모두 127.0.0.1에만 바인딩되며 `/api/v1`만 127.0.0.1:8765로 프록시합니다. 백엔드도 loopback에만 바인딩됩니다. 외부 공개용 서비스 구성이 아닙니다.

로그아웃은 서버 세션을 폐기하고 쿠키를 삭제합니다. 서버의 Bearer 토큰을 교체하면 과거 웹 세션은 무효화되어 다시 로그인해야 합니다. 세션은 서버 데이터 디렉터리의 별도 파일에 세션 ID 해시로 저장됩니다. 브라우저 저장소에 원본 토큰을 보관하지 않습니다. 쿠키 인증으로 내용을 변경하는 요청은 같은 출처의 `Origin`과 `X-Haejumi-Web` 헤더를 요구합니다. 로컬 HTTP에서는 Secure 쿠키를 사용하지 않으며 검증된 사설 HTTPS 프록시에서만 `HAEJUMI_WEB_COOKIE_SECURE=true`로 설정합니다. Android는 기존 Bearer 인증을 계속 사용합니다.

## 현재 범위

예투는 인사·감정 표현을 기록 저장과 구분하며, 동의된 현재 입력 문구만 외부 AI 해석 대상으로 삼습니다. 외부 AI가 꺼져 있으면 자유 대화 응답이 제한됩니다. 홈에서 최근 로컬 대화 이력을 보고 삭제할 수 있습니다. 과거 대화는 외부 요청에 자동 첨부하지 않습니다.

- 예투 홈의 규칙 기반 대화, Creator 사용 가능 카드와 Schedule·Wellness·Diary 준비 중 카드.
- 수동 파일 선택·해시 검증·업로드·프로젝트 생성, 소유 프로젝트 목록.
- 서버에서 다시 읽은 기획·자막 초안·체크포인트, 버전 기반 수정·중간 승인, 렌더 요청·상태·취소, 인증된 실제 FFmpeg MP4 해시 확인 후 재생.
- HTTP 409 충돌 시 서버의 최신 작업을 다시 조회. 주기적 조회와 탭 복귀 시 조회로 다른 기기의 변경을 반영.

PC 웹은 플랫폼별 게시 정보·독립 최종 승인, 구조화 장면 편집과 Creator Vision 동의 화면을 제공합니다. Vision 화면은 대상 media_id, 전송 상한, 예상 예약 비용을 보여주고 사용자가 선택한 경우에만 범위 동의를 발급해 기획 요청에 전달합니다. 서버 외부 AI 실행 설정은 기본 비활성이며 실제 유료 Vision 호출은 아직 검증하지 않았습니다. PC 음악 등록·권리 증빙 UI와 음성/STT는 후속입니다. Android 실기기 동작은 검증되지 않았으며 실제 SNS 게시는 없습니다.

## 테스트

`npm test`는 API 요청 구성·선택 업로드 manifest·안전 오류 메시지 단위 테스트입니다. `npm run build`는 React 산출물 빌드입니다. Android 실기기와 두 기기 간 실제 동시 동작은 별도 검증이 필요합니다.
