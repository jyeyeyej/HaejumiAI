# 단계별 승인 워크플로(Human-in-the-Loop)

> 해주미 v0.2 · 2026-10-30 · [확정] 사용자 최종 통제권

## 공통 원칙
- 예투는 사용자를 존댓말로 응대합니다. 사용자는 텍스트 또는 음성(STT)으로 수정·승인 의사를 전달할 수 있습니다.
- **중간 승인 = 다음 작업 단계 진행 허용**, **최종 승인 = 정식 일기 저장 또는 외부 SNS 게시 허용**으로 권한을 구분합니다.
- 중간 승인 체크포인트에서 `승인하고 다음 / 수정 요청 / 보류 / 취소`를 제공합니다.
- 초안은 재개 가능한 임시 저장을 허용하지만, 최종 승인 전 확정 일기로 저장하거나 공개 게시하지 않습니다.
- 승인한 `task_id + checkpoint_id + content_version + sha256`이 실제 실행 대상과 같아야 합니다.
- 수정하면 새 버전을 만들고 영향받은 단계의 승인을 무효화합니다.
- 동일 승인·게시 요청은 idempotency key로 중복 처리하지 않습니다.

## 콘텐츠 승인 단계
1. 사용자 선택 미디어 업로드 완료 → 예투의 제작 제안(수락/보류/취소).
2. **기획 컨펌:** 컷·순서·길이·스타일·채널 형식 확인.
3. **음악·자막 컨펌:** 미리 듣기, 자막 수정, 생성 음악 라이선스 확인.
4. **영상 컨펌:** FFmpeg 렌더 미리보기, 피드백, 재렌더 반복.
5. **권리 검사:** 에셋 출처·상업 이용·플랫폼별 게시 조건 검사. 실패 시 게시 차단.
6. **최종 게시 승인:** 영상 버전·해시·제목·해시태그·플랫폼·공개범위를 보고 확인.
7. **게시 Tool:** 승인된 버전만 공식 API로 전송; 성공 URL/실패 사유 기록.

## 일기 승인 단계
1. 사용자가 허용한 일정/감정/건강 기록 조회. 예정 일정의 실제 수행 여부 질문.
2. **사실·구성 컨펌:** 오늘의 주요 사건·감정 요약 확인, 오해 수정.
3. **초안 컨펌:** 문체·세부내용 수정; 텍스트/음성 피드백 반복.
4. **최종 컨펌:** 최종 문장 전체 제시, 승인 여부 확인.
5. **정식 저장:** 승인 버전만 `diary_entries`에 저장; 미승인본은 `diary_drafts`로 유지.

## 상태 모델
`CREATED → PLANNING → WAITING_PLAN_APPROVAL → DRAFTING → WAITING_DRAFT_APPROVAL → RENDERING/REVISING → WAITING_FINAL_APPROVAL → APPROVED → SAVING/PUBLISHING → SUCCEEDED`

예외: `ON_HOLD`, `REJECTED`, `CANCELLED`, `FAILED`, `RIGHTS_BLOCKED`, `STALE_APPROVAL`.

## 보안 및 테스트
- 구버전 승인 요청은 409 거절. 승인 후 영상·텍스트 변경 시 재승인.
- 사용자 응답 없이 대기 중인 작업을 자동 진행하지 않습니다.
- 동시 요청·앱 종료·네트워크 단절 이후에도 상태가 일관되어야 합니다.
- 공개 게시 API 정책상 불가능한 경우 '게시 완료'로 표시하지 않고 수동 공유로 전환합니다.

## v0.3 — 승인과 부분 재실행
- 중간 수정 시 이전 모델 산출물을 캐시하고 수정 범위만 재처리한다.
- 초안 버전이 바뀌면 기존 최종 승인을 재사용할 수 없으며, 비용 한도 도달 시에도 승인/권리 검사를 건너뛰지 않는다.
