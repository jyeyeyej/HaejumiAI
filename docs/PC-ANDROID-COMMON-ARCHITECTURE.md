# Android·PC 공통 기능 구조

> 2026-11-03 사용자 확정 방향(D123~D125). 현재 구현과 후속 목표를 구분합니다.

## 실행 경계

| 계층 | 현재 역할 | 상태 |
|---|---|---|
| Android Kotlin/Compose | Photo Picker 선택 업로드, Creator 검토·승인 UI | 코드 있음, 실기기·사설 HTTPS 미검증 |
| Windows PC React 웹 | 예투 홈, 선택 업로드, Creator 프로젝트/기획/초안/렌더/미리보기 | 첫 버전 구현, 브라우저 E2E 미검증 |
| Node.js `/api/v1` | 인증·소유권, 파일 검사, Agent 라우팅, 버전·승인, PrivacyGate, 비용·권리 게이트, FFmpeg | 공통 참조 백엔드; 최종 기술 스택 결정은 아님 |
| 서버 로컬 저장소 | 미디어, 프로젝트, 작업, 체크포인트, 승인, 렌더 결과 | 유일한 현재 데이터 원천 |

클라이언트의 임시 입력·미리보기 캐시는 서버 결과를 대체하지 않습니다. 브라우저 토큰은 탭 메모리, Android 토큰은 Keystore 기반 암호화 저장을 사용합니다. PC 웹과 백엔드는 127.0.0.1에만 바인딩하고, Android는 안전한 사설 HTTPS 경로를 구성·검증한 뒤 연결합니다. 임의의 LAN/공용 바인딩은 허용하지 않습니다.

## 버전과 동시 수정

1. 두 클라이언트는 `GET /content/projects`, `GET /tasks/{task_id}`, `GET /tasks/{task_id}/checkpoints`, `GET /tasks/{task_id}/jobs`로 서버 상태를 다시 읽습니다. 각각 인증된 소유자만 조회합니다.
2. 기획/자막 변경은 현재 `content_version`과 필요한 경우 `content_hash`를 보냅니다. 서버가 불일치와 구버전 승인을 HTTP 409로 거절하고, 영향받은 승인을 무효화합니다. 클라이언트는 409 뒤 새 상태를 읽고 사용자가 다시 확인하도록 합니다.
3. 모든 쓰기 요청은 멱등 키를 사용합니다. 키와 요청 본문은 같은 재시도에만 재사용합니다. 브라우저 자동 동기화는 읽기 요청만 수행합니다.
4. 브라우저 탭 복귀 및 주기 조회는 표시 지연을 줄일 뿐 실시간 동기화 보증은 아닙니다. 실제 Android↔PC 동시 수정·네트워크 단절 E2E는 별도 검증합니다.

## 안전 경계

- PC는 파일 선택창에서 고른 파일만 읽습니다. 폴더 열람·백그라운드 감시·갤러리 자동 탐색은 없습니다.
- 외부 LLM에는 개인 자료를 기본 전송하지 않습니다. 웹 첫 버전에는 외부 처리 동의 UI와 `privacy_consent_id` 전달이 없습니다. 서버 PrivacyGate와 비용 한도는 공통 적용됩니다.
- 중간 승인은 다음 단계만 허용합니다. SNS 게시와 일기 최종 저장은 서버의 현재 버전·대상·권리·최종 승인 게이트가 필요합니다. 실제 SNS 게시 경로는 구현되지 않았습니다.
- 음원 권리의 사용자 확인 기록은 법률 검증 보증이 아닙니다. 미확인 권리는 서버의 플랫폼별 최종 승인에서 차단합니다.
