# 모니터링·로그·복구

> 프로젝트: **해주미(Haejumi)** · AI 비서 이름: **예투**  
> 상태: 설계 초안 v0.2 · 수정일: 2026-10-30 · 대상: 1인 개인용, 향후 다중 사용자 확장  
> 원칙: **존댓말 응답 / 크리에이터 상업적 수익화 / 권리 검증 / 사용자 통제 / 로컬 우선**  
> 표기: **[확정]** 합의된 목표 · **[제안]** 구현 선택 · **[검증 필요]** 정책·환경 확인 전 결정 보류

## 핵심 목표
작업이 왜 실패했는지, 어떤 Agent/Tool이 어떤 결정을 했는지 추적하고 오류를 안전하게 복구합니다.

## 로깅 표준
- `trace_id`, `task_id`, `project_id`, `agent`, `step`, `tool`, `started_at`, `duration_ms`, `status`, `error_code`, `attempt`.
- 원본 사진 경로, OAuth 토큰, 감정·건강 원문, 음악 생성 프롬프트 내 비밀은 로그에 마스킹.

## 기본 대시보드
- 작업 대기/실행/완료/실패 건수.
- 평균 렌더 시간, 실패 사유 TOP, 영상 생성 재시도율.
- 제안 수락률, 권리 차단 건수, 게시 성공률.
- 모델 토큰 및 API 비용/로컬 GPU 처리 시간(가능 범위).

## 오류 대응
| 오류 | 복구 정책 |
|---|---|
| 외부 API 429/5xx | 제한적 지수 백오프, 토큰/권한 문제와 분리 |
| 렌더 실패 | 입력 상태 검증 후 최대 N회 재시도 |
| 저작권 차단 | 자동 재시도 금지, 사람 검토 |
| 게시 응답 타임아웃 | 결과 상태 확인 전 동일 게시 재호출 금지 |
| PC 중단 | DB/큐의 체크포인트에서 재개 |

## 운영자 화면
작업 이력 → 각 단계 → 도구 응답 요약 → 재시도 횟수 → 권리 판단 근거 → 수동 중지 버튼.

`task_id, agent, user_id, import_id, checkpoint_id, approved_version, approved_hash, decision, input_mode(text|voice), render_job_id, publish_id`를 상호 연결합니다.
