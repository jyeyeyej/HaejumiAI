## 기억 계층

2026-11-04 구현 정책: 예투의 대화 문구와 응답은 PC 로컬 서버의 소유자별 기록으로 최근 30일·최대 100건만 조회합니다. 사용자는 웹·Android에서 이력을 조회하고 현재 저장소의 이력을 삭제할 수 있습니다. 자유 대화와 감정 표현은 Wellness·Diary에 자동 저장하지 않습니다. 과거 이력은 외부 AI에 자동 첨부하지 않으며, 별도의 명시적 전송 범위 동의 설계 전까지 외부 요청은 현재 입력 문구에 한정합니다. 기존 로컬 백업 사본에는 삭제 전 대화가 남아 있을 수 있으므로 백업 삭제·보존 기간은 후속 운영 정책으로 검증해야 합니다.
| 구분 | 예 | 저장·회수 방식 | 보존 |
|---|---|---|---|
| 프로필/선호 | 존댓말, 여행·맛집, 영상 스타일 | 구조화 테이블 | 삭제 요청 전 |
| 장기 기억 | 선호 자막·음악 템포, 반복 수정 | 승인된 사실/선호 이벤트 | 수정·삭제 가능 |
| 단기 맥락 | 현재 편집 프로젝트, 오늘 요청 | task/context + TTL | 기간 제한 |
| 업무 기억 | 진행 프로젝트·보고서 템플릿 | 문서+벡터 검색 | 명시 보관 |
| 민감 기록 | 감정·수면·건강 | 별도 테이블·권한 | 짧은 기본 보존 검토 |

## 기억 생성 규칙
1. 사용자 명시 설정은 바로 프로필에 반영할 수 있습니다.
2. AI가 추론한 선호는 `proposed`로 표시하고 사용자 승인 후 `active`로 변경합니다.
3. 관찰값과 추정값을 분리해 `source`, `confidence`, `confirmed_by_user`, `updated_at` 기록.
4. 오래된 기억과 충돌하면 자동 덮어쓰기보다 확인 요청.
5. RAG 검색 시 필요한 범위만 최소 조회, Wellness 데이터는 Creator 기본 접근 금지.

## 최소 모델
- `user_preferences(key, value_json, source, approval_status, updated_at)`
- `memory_items(id, category, text, embedding, source_ref, sensitivity, expiry_at)`
- `memory_audit(id, actor, action, item_id, timestamp)`

## 사용자 권리
- 기억 목록, 근거, 수정·삭제, 관련 파일 내보내기, '이건 기억하지 마세요' 제공.
- 로그·백업에도 민감정보가 장기간 잔존하지 않도록 보존 정책을 정의합니다.

## v0.2 일기·승인 기억
- 일기는 `draft`와 `final`을 별도 상태로 관리하고, 승인되지 않은 초안을 확정된 기억으로 취급하지 않습니다.
- 일정의 예정 정보와 실제 수행 확인 정보를 구분하여 일기의 허구 생성을 방지합니다.
- 장기 기억 반영은 사용자 동의에 따라 수행하며, 감정·건강·일기 데이터는 최소 범위 조회 및 삭제/수정 가능하게 합니다.
- 음성 원본은 기본적으로 변환 후 보존하지 않는 방향(별도 동의 시 예외)을 제안합니다.

## v0.3 — 기억 조회 비용 제한
- 에이전트가 필요한 기간·유형의 메모리만 조회한다. Diary에는 하루 일정·감정·건강과 사용자가 확인한 정보만 제한적으로 제공한다.
- 긴 원문 대화/전체 일기 컬렉션을 모든 LLM 요청에 자동 첨부하지 않는다.
