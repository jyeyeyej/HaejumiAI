> 프로젝트: **해주미(Haejumi)** · AI 비서 이름: **예투**  
> 상태: 설계 초안 v0.2 · 수정일: 2026-10-30 · 대상: 1인 개인용, 향후 다중 사용자 확장  
> 원칙: **존댓말 응답 / 크리에이터 상업적 수익화 / 권리 검증 / 사용자 통제 / 로컬 우선**  
> 표기: **[확정]** 합의된 목표 · **[제안]** 구현 선택 · **[검증 필요]** 정책·환경 확인 전 결정 보류

## 원칙
먼저 알리는 AI를 만들되 **무단 제작·무단 게시가 아니라 사용자의 선택을 돕는 제안**으로 구현합니다.

## 제안 규칙 v0.1 [제안]
- 후보: 사용자가 직접 선택해 업로드 완료한 신규 미디어 묶음.
- 업로드 완료: 파일 크기·manifest 검증 후 제안(파일 복사 중에는 시작하지 않음).
- 중복: `group_fingerprint + proposal_type` 고유 키로 같은 후보의 중복 알림 차단.
- 빈도: 하루 최대 제안 수·방해 금지 시간 설정.
- 개인화: 사용자 선호 여행/맛집, 이미 게시한 장소, 제안 수락률 반영.

## 제안 상태
`DETECTED → ELIGIBLE → PROPOSED → ACCEPTED | SNOOZED | DISMISSED | EXPIRED`

## 사전 동의 관리
- 그룹 감지 opt-in, 알림 opt-in, 원본 업로드 opt-in을 별도 설정.
- AI가 무심코 개인 사진을 보내거나 제3자에게 공개하지 않도록 전송/게시 경계를 분리.
- 자동 게시 허용 규칙을 설정하더라도 플랫폼별 권한과 권리 게이트는 우회 불가.

## 알림 예시
> “어제 촬영하신 카페 사진 8장과 영상 2개를 묶어 보았습니다. 30초 쇼츠로 편집해 드릴까요?”

버튼: `제작하기`, `나중에`, `이번 장소는 제외`.

## 평가 지표
- 제안 수락률, 오탐 묶음 비율, 알림 피로도(차단/무시), 파일 중복 업로드율, 사용자의 수동 수정 횟수.

## v0.2 능동형 제안 트리거 변경
**확정 트리거는 Android 사용자가 선택한 사진·영상의 업로드 완료 이벤트입니다.** 갤러리 전체 백그라운드 모니터링은 사용하지 않습니다.
1. Android 선택 업로드 완료 → 서버에서 파일·manifest 검증.
2. 동일 `manifest_hash + user_id`의 기존 제안 여부 확인.
3. 예투가 '선택하신 사진 8장과 영상 2개로 쇼츠를 만들어 드릴까요?' 알림.
4. `제작하기/나중에/취소` 중 선택 → 선택 후 기획 확인으로 이동.
5. 기획·음악·자막·최종본은 `23-APPROVAL-WORKFLOW.md`에 따라 컨펌.
향후 *별도 opt-in*으로 전체 갤러리 사진 묶음 탐색을 재검토할 수 있으나 현재 MVP에는 포함하지 않습니다.
