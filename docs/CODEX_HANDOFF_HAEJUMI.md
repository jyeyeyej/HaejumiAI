## 0. Codex에 요청하는 핵심 작업

사용자와 대화만 하는 챗봇이 아니라, 모바일에서 실제 파일을 올리고 PC에서 영상이 만들어지며, 휴대폰에서 검토·수정·승인 후 허용된 SNS에 게시하는 **동작 가능한 해주미 MVP**를 단계별로 개발한다.

**코딩 원칙**
1. 기존 저장소/설계 문서를 먼저 읽고, 파일·구조를 파악한 후 수정한다. 기존 구현을 무작정 삭제하지 않는다.
2. 사용자가 확정한 기능은 유지하고, 임의로 요구사항을 생략하거나 다른 서비스로 바꾸지 않는다.
3. 먼저 작동하는 얇은 흐름(end-to-end vertical slice)을 만든 뒤 확장한다.
4. 구현한 단계마다 테스트·실행법·남은 제약·변경 파일을 문서로 남긴다.
5. **상업적 이용·권리 증빙·최종 승인·개인정보 보호**는 속도나 비용 때문에 우회하지 않는다.
6. 확인되지 않은 기능은 성공한 것처럼 표시하지 않는다. 모의(Mock)/실서비스 연결을 명확히 구분한다.
7. UI 대화 및 AI 비서 '예투'는 한국어 **존댓말**, 문서 형식은 **노션에 붙여넣기 쉬운 Markdown**을 기본으로 한다.

## 1. 서비스 정체성 및 목표

- **서비스명:** 해주미(Haejumi AI)
- **AI 비서 이름:** 예투
- **사용자:** 처음에는 본인 1명. 추후 여러 사용자가 가입할 수 있도록 사용자 ID·접근권한 등의 확장성만 고려하고, 처음부터 SaaS 구축은 하지 않는다.
- **기기:** Android 휴대폰이 주 사용 기기. Windows PC(필요 시 WSL2/Docker)가 로컬 AI 처리/영상 렌더링 서버.
- **목적:** 크리에이터가 되어 **상업적으로 수익화할 수 있는** 직접 촬영 사진·영상으로 쇼츠/릴스/피드를 꾸준히 제작하고, 개인 일정·건강·감정·일기도 함께 관리한다.
- **운영:** 클라우드 배포는 MVP 필수 아님. 같은 Wi-Fi에서 시작해 외부 접근이 필요하면 Tailscale 등 사설 네트워크 사용. PC가 꺼지면 PC측 렌더링/AI 작업이 중단 또는 대기됨을 안내.
- **금지:** 휴대폰 전체 갤러리 무단 스캔, 사용자 최종 승인 없는 정식 일기 저장·SNS 공개 게시, 라이선스 미확인 미디어 자동 게시.

## 2. 최종 4개 전문 에이전트

| 에이전트 | 핵심 기능 | 범위 |
|---|---|---|
| **Creator Agent (최우선)** | 사진·영상 선택 업로드 → 장면 분석 → 영상/사진 편집 → 자동 자막 → 무료 상업용 BGM → 단계별 컨펌 → 저작권 확인 → SNS 게시 | MVP 중심 |
| **Schedule Agent** | 캘린더 연동, 일정 등록/변경/조회, 할 일, 알림 | 후속 |
| **Wellness Agent** | 기분·스트레스·수면·운동·생활 기록, 패턴 회고, 자기관리 안내(진단 금지) | 후속 |
| **Diary Agent** | 그날의 실제 일정+사용자가 제공한 감정·건강·대화 정보를 종합한 일기 초안, 수정, 최종 승인 후 정식 저장 | 후속 |

- **Work Agent(기획안/보고서 전담)**는 최신 결정에 따라 홈 화면의 핵심 에이전트에서 **제외하고 Diary Agent로 교체**한다.
- **Supervisor '예투'**가 요청을 분류, 필요한 에이전트를 선택/순서 결정, 결과 통합, 승인·실패 복구를 관리한다.
- 단순 요청은 룰 기반 라우터로 처리하고 복합/모호한 요청에만 소형 LLM을 사용한다.

## 3. Creator Agent 사용자 흐름 (필수)

### 3.1 입력 및 제작 제안
1. 사용자가 **Android 앱에서 갤러리 중 원하는 사진·영상만 선택**한다(Android Photo Picker 권장).
2. 앱 내에서 새 콘텐츠 프로젝트(예: '카페 방문')를 선택/생성한다.
3. 선택한 파일만 **FastAPI로 업로드**, PC의 `data/uploads/<project_id>/`에 안전하게 저장한다. 부분 업로드·중복 전송 감지, 원본 수정/삭제 금지.
4. 업로드가 완료되면 예투가 먼저 “선택하신 사진·영상으로 쇼츠를 만들어 드릴까요?”라고 **제작 제안**한다. 사용자는 제작 / 나중에 / 취소를 고른다.
5. **초기에는 전체 갤러리 상시 감지 불필요.** 능동형 제안 트리거는 사용자가 직접 선택한 파일의 **업로드 완료 이벤트**이다.

### 3.2 중간 컨펌과 편집
6. AI가 사진·영상의 메타데이터/분위기/사용 가능한 클립을 분석한다. 우선 기본 규칙·FFprobe·OpenCV 사용. 필요할 때만 비전 LLM.
7. **기획 컨펌:** 장면 선택, 순서, 영상 길이(기본 15~30초), 화면 비율(9:16), 톤을 제시하고 승인/수정/보류를 받는다.
8. **자막:** 원본에 음성이 있으면 로컬 STT(faster-whisper 등)로 전사·타이밍; 사진 기반에는 AI가 짧은 소개 문구 생성. 자막 텍스트/위치/스타일 수정 가능.
9. **음악:** 처음에는 **무료이며 상업용 영상 사용이 허가된 로컬 음원 5~10곡으로 시작 → 20~30곡 확장**. 분위기 태그로 자동 선택. 해당 SNS 사용 권한이 확인된 음원만 후보. 음악·자막 중간 컨펌.
10. FFmpeg(필요 시 Pillow/OpenCV)로 원본 사진+촬영 영상을 결합하고 화면 전환/간단 보정/자막/BGM/페이드를 적용하여 MP4 생성. 말소리가 필요하면 음악과 오디오를 믹스한다.
11. **모바일 미리보기 컨펌:** 휴대폰에서 결과물 재생, 장면/자막/음악 수정. 수정 시 **변경 부분만 재처리**한다.
12. **권리 검증:** 음원·폰트·사진·영상 등 라이선스 기록, 플랫폼별 권한, 필요한 표시, 콘텐츠 품질(영상 길이/코덱/자막 오버플로 등) 확인.
13. **최종 게시 컨펌:** 사용자에게 최종 파일, 버전, 제목/설명/해시태그, 대상 SNS 계정, 공개 설정을 명시하고 **최종 승인**을 받는다.
14. 승인된 **정확한 버전만** SNS API가 허용하는 범위에서 게시한다. 결과(업로드 ID/URL/상태/오류)를 기록하며 중복 게시 금지.

### 3.3 SNS 게시 제약
- YouTube: 공식 Data API + Google OAuth 권한으로 최초 연동 목표. 실제 앱/계정 상태·검증 요구·할당량을 확인.
- Instagram: 공식 API와 지원 계정 유형(프로페셔널 계정 등), 공개 접근 가능한 업로드 URL/게시 권한의 요구조건을 확인한 다음 구현.
- TikTok: 개인 전용 자동 공개 게시 도구는 공식 API의 앱 심사·허용 사용 사례 제약이 있을 수 있다. **무조건 자동 게시 가능하다고 약속하지 말 것.** 허용되지 않으면 '완성 파일 내보내기/기기 앱 공유/공식 승인된 초안 업로드' 등 준수 가능한 대안을 제공.
- 계정 연결정보는 백엔드에 보관. OAuth 접근 토큰은 암호화하고 갱신·취소·만료 처리.
- 최종 사용자 승인이 없는 SNS 공개 게시 **금지**. 앞으로 자동 게시 모드를 추가할 경우에도 규칙/범위/수신 계정을 명시적으로 사전 승인받고 기본 OFF로 한다.

## 4. 일기·일정·웰니스 핵심 흐름

**Diary Agent:**
1. 오늘 날짜의 캘린더 일정 + 사용자가 직접 남긴 감정·수면·건강·대화 기록 등 **접근을 허용한 정보만** 조회.
2. '예정된 일정'과 '실제로 수행한 일'은 구별. 없는 감정/사건을 지어내지 않고 확인이 필요하면 질문.
3. 반영할 정보 확인 → **일기 초안 작성** → 문단/어투 수정 피드백(텍스트·음성) → 수정본 미리보기 → **최종 승인 시에만 정식 저장**.
4. 미완료 초안은 별도 상태로 보관해 이어서 작성. 일기 문체는 사용자 선호에 따르되 예투 대화 말투는 존댓말.
5. 주간/월간 회고는 이후 기능. 감정·건강 상태에 대해 의료 진단을 단정하지 않는다.

**Schedule Agent:** Google Calendar OAuth, 일정 조회/등록/수정/삭제, 알림; 민감하거나 외부에 영향 주는 변경은 확인.

**Wellness Agent:** 감정·수면·운동·컨디션 기록 및 생활 패턴 요약. 사용자가 기록/연동한 실제 정보만 사용하고 건강 데이터는 별도 접근통제.

## 5. 텍스트와 음성의 공통 입력

- 모든 주요 요청 및 **중간 수정 요청**은 텍스트와 음성(STT) 모두 지원.
- 모바일 마이크 → STT → **인식된 텍스트를 사용자에게 보여주고 수정 가능** → 동일한 Supervisor 입력 경로.
- 후보: Android SpeechRecognizer(플랫폼/네트워크 의존성 확인) 또는 PC 측 로컬 `faster-whisper`.
- 오인식·권한 거부·오프라인·취소 시 오류 처리. 민감한 원본 음성은 최소 보관/자동 삭제 정책; 원본 녹음의 임의 장기 저장 금지.
- 예투 TTS 음성 응답은 선택적 후속 기능.

## 6. 공통 승인/상태 관리 (HITL) — 절대 생략 금지

다음 상태를 명시적으로 모델링한다.

`CREATED → PLAN_REVIEW → DRAFTING → DRAFT_REVIEW → REVISING → FINAL_REVIEW → APPROVED → (SAVED | PUBLISHING → PUBLISHED)`

보류/취소/실패 상태 `PAUSED`, `CANCELLED`, `FAILED`, `BLOCKED_BY_RIGHTS`도 필요.

- 중요 단계마다 승인/수정 요청/보류/취소 UI.
- LangGraph `interrupt`+영속 체크포인트 또는 동등한 백엔드 상태 머신 사용.
- `task_id`, `draft_version`, `artifact_hash`, `approval_type`, `approved_version`, `approved_at` 등 서버에서 검증.
- 중간 컨펌은 최종 승인 아님. **최종 승인을 받은 최신 버전**만 정식 일기로 저장하거나 SNS에 공개 게시.
- 승인 후 결과물이 바뀌면 기존 승인 자동 무효화, 재승인 필수.
- 앱 종료·PC 재시작 후 대기 작업 복원.
- 동일 승인/게시 요청 재전송 시 **멱등성 키**로 중복 작업 방지.
- 최종 일기 저장 전 초안은 `draft` 상태로 별도 보관 가능.
- 권리 위반·인증 만료·게시 오류는 사용자가 알 수 있게 표시하고 자동 게시 차단.

## 7. 상업적 사용/저작권 정책 (핵심 제약)

- 사용자는 크리에이터 수익화가 최종 목적. **비상업용(NC) 모델·음원·폰트 등은 상업 콘텐츠 생성 경로에서 제외.**
- 음악은 1차적으로 **사용자가 직접 확인·다운로드한 상업용 허가 무료 음원**을 로컬 라이브러리에서 선택. Mixkit/Pixabay 등은 후보일 뿐, 개별 곡/플랫폼 이용조건 확인 전 승인 처리 금지.
- 곡당 기록: 원곡명, 작곡가, 원본 URL, 다운로드 일자, 적용 라이선스/버전/증빙, 허용 플랫폼, 표시 의무, `rights_status`.
- `rights_status=verified`이고 해당 사용 플랫폼/용도가 허용될 때만 자동 선택·게시.
- '무료' 또는 'royalty-free'만으로 무조건 수익화/다중 플랫폼 사용 가능하다고 간주하지 말 것. Content ID 클레임 가능성을 관리하고 근거 없는 '저작권 100% 안전' 표시는 금지.
- 상업 이용 가능한 **AI 음악 생성**은 추후 플러그인/모듈로 확장. 선택 모델의 라이선스·상업 사용 조건과 PC 처리 성능을 최신 공식 조건으로 검증 후 도입.
- 타인 초상권, 로고/상표, 매장 촬영 규칙, 협찬/광고 표시 문제도 최소한 검토 항목으로 둔다.
- 불확실하면 사용자에게 이유 표시 후 **게시 차단**.

## 8. LLM 사용 비용 최소화 — 반드시 설계에 포함

**원칙:** 룰/일반 코드 → 로컬 도구/모델 → 저가 소형 클라우드 LLM → 고성능 모델(필요 시) 순서로 사용.

| 작업 | 기본 기술 | LLM 호출 |
|---|---|---|
| 갤러리 선택, 업로드, 폴더 저장 | Android Photo Picker, FastAPI | 0 |
| 영상 편집, 인코딩, 자막 합성 | FFmpeg / Pillow | 0 |
| STT | 기기 STT / faster-whisper | 클라우드 LLM 불필요 |
| 음악 자동 선택 | 태그·분위기 점수 | 기본 0 |
| 중복 파일 검사 | 해시/메타데이터 | 0 |
| 일정 조회 | API/규칙 처리 | 0 |
| SNS 게시 | OAuth + 플랫폼 API | 0 |
| 일기·자막·해시태그 작성 | 저비용 소형 LLM | 필요할 때만 |
| 복합 요청·심층 분석 | 로컬/소형 모델 우선 | 꼭 필요할 때만 |

- “음악만 바꿔주세요” → 음악 재선택 및 오디오 재합성만, 기존 사진 분석·자막 생성 재호출 금지.
- “일기 둘째 문단 수정” → 해당 문단과 최소 문맥만 전달, 전체 재작성 금지.
- 반복 프롬프트·관련 기억 검색·캐시 활용; 이전 전체 대화/모든 사진을 매번 재전송하지 않음.
- **초기 실험 예산 제안:** 하루 `$0.20`, 월 `$5.00`, 작업당 최대 LLM 5회, 수정 3회(사용자 설정으로 조정 가능). 제품 정책 값이지 API 회사가 자동 강제하는 값이 아님.
- `LLM Gateway`에서 토큰/예상비용, 제공자, 재시도, 오류, 잔액 검사 및 로그를 관리; 예산 초과 시 추가 LLM 호출 보류.
- 가격/요금/모델명은 하드코딩하지 말고 실제 도입 시 공식 요금표 확인. API 키 유출 방지.

## 9. 제안 기술 스택 (확정 기능과 구현 선택 분리)

| 계층 | 초기 제안 | 비고 |
|---|---|---|
| Android | Kotlin + Jetpack Compose | 모바일 우선, Photo Picker, 알림 |

| Orchestration | LangGraph | Supervisor 및 HITL, 필요 시 상태기계 |
| DB | PostgreSQL + pgvector | 작업, 승인, 기억, 일기 |
| 작업 큐/스케줄링 | 우선 간단한 Worker → 필요 시 Redis 큐 | 초기 과설계 금지 |

| STT | Android STT / faster-whisper | 로컬 우선 |
| 음악 | 권리 확인된 로컬 무료 음원 DB | AI 작곡은 후순위 |
| 로컬 운영 | Docker Compose (Windows/WSL2) | NAS/클라우드 필수 아님 |
| 외부 접속 | Tailscale (선택) | 인터넷에 서버 포트 무방비 노출 금지 |

| 스토리지 | 로컬 파일 + DB 메타데이터 | S3는 추후 다중사용자 확장 시 고려 |

## 11. API/DB 최소 계약 가이드 (세부는 기존 문서 참고)

- `POST /api/projects` : 콘텐츠 프로젝트 생성
- `POST /api/projects/{id}/media` : 사진·영상 업로드(파일 유형/크기/해시 검증)
- `POST /api/projects/{id}/propose` : 제작 제안 상태 생성
- `POST /api/tasks/{id}/plan` : 편집 기획 생성/조회
- `POST /api/tasks/{id}/feedback` : 단계별 수정 요청
- `POST /api/tasks/{id}/approve` : 단계별 승인, **서버에서 version+hash 확인**
- `GET /api/tasks/{id}` : 상태 조회
- `GET /api/tasks/{id}/preview` : 접근 제어된 결과 미리보기
- `POST /api/tasks/{id}/publish` : 최종 승인+권리 검증 후 멱등 게시
- `POST /api/diaries/drafts`, `POST /api/diaries/{id}/approve` : 일기 초안/최종 저장(후속)
- 엔드포인트는 제안이며, 기존 `09-API-CONTRACT.md`와 비교 후 합의된 한 계약으로 정리할 것.

필수 엔터티: `users`, `media_projects`, `media_assets`, `creator_tasks`, `task_versions`, `approvals`, `music_tracks`, `license_evidence`, `publish_jobs`, `publish_results`, `llm_usage`, `diary_drafts`, `diaries`, `wellness_records`, `calendar_links`.

## 12. 환경변수와 키 관리

**사용자가 직접 준비/승인해야 하는 항목:** OpenAI API Key(클라우드 모델을 쓸 때), Google OAuth(YouTube/Calendar), Meta 개발자 앱 인증정보(Instagram), TikTok 개발자 앱 인증정보 및 게시 권한(허용 시). 음악/FFmpeg/faster-whisper/로컬 DB는 별도의 외부 유료 API 키가 필요하지 않음.

- 루트 `.env.example`은 예시 이름만, 실제 `.env`는 Git 추적 제외.
- 모바일 앱/React 번들에 API Secret 절대 포함 금지.
- OAuth 토큰은 서버 측 암호화 저장, 갱신/해제 지원.
- 연결 전에는 SNS 업로드를 **테스트/모의 모드**로 표시.
- 개인 사진·건강 기록·일기·음성은 접근 제한, 최소 저장, 백업/삭제 정책 적용.

## 13. 단계별 개발 지시 / 완료 기준

### Phase 0 — 기존 자료 점검 + 실행 환경
- 프로젝트 파일과 `docs`를 먼저 읽는다. 문서 상충 사항을 목록화한다.
- Docker/FastAPI/FFmpeg/테스트 환경을 재현 가능하게 만든다.
- `.env.example`, `.gitignore`, 로컬 데이터 디렉터리 생성. 민감정보 커밋 차단.

### Phase 1 — 핵심 Creator 기능 검증 (첫 번째 목표)
- Android에서 *선택한* 사진/영상 업로드 또는 **임시 개발용 업로드 UI** → PC 프로젝트 폴더 저장.
- 사진+영상으로 9:16 MP4(기본 30초 이내) 제작.
- 적법한 무료 음원 1~5개를 수동 등록하고 태그로 추천, 실제 자막 삽입.
- 제작 방향/음악·자막/최종본 **중간·최종 컨펌**, 버전 수정, 프리뷰.
- 저작권 미검증 자산이면 게시 막기.

**수용 기준:** 소유한 카페 사진 8장과 짧은 영상 2개를 지정해 하나의 쇼츠를 만들고, 모바일에서 수정 요청 후 새 버전을 확인할 수 있어야 한다.

### Phase 2 — 모바일 사용성 + 예투 제안
- Android Photo Picker, 업로드 상태, 제작 제안 알림/앱 화면, 미리보기/수정 음성 입력.
- PC가 꺼진 경우 재시도·대기 상태 안내 및 안전한 재개.

### Phase 3 — SNS 게시 실연동
- YouTube OAuth/승인된 영상 게시/업로드 로그/중복 게시 방지부터 구현.
- Instagram/TikTok은 공식 정책을 확인해 **가능한 기능만** 추가.

### Phase 4 — 개인비서 확장
- Schedule, Wellness, Diary Agent 및 Supervisor 통합.
- 일정+감정+건강 기반 일기 초안, 텍스트/음성 수정, 최종 승인 후 정식 저장.

### Phase 5 — 고도화
- 상업 사용 가능한 AI 음악 작곡 모델, 사용자 취향 기억, 콘텐츠 성과 분석, 고급 스케줄링, 필요 시 다중 사용자 대응.

**각 단계 완료 시 반드시 보고**
- 실제 실행 명령/필요한 환경변수
- 완료한 기능과 테스트 결과(실제/Mock 구분)
- 바뀐 파일·DB 마이그레이션 목록
- 남은 정책·라이선스·권한 검증 과제
- 다음 개발 순서

## 14. 첫 작업으로 Codex가 수행할 것

1. 현재 저장소와 `docs` 구조를 검토하고 기존 구현이 무엇인지 확인.
2. 이 문서를 기준으로 **요구사항 충돌/누락 목록** 작성. 특히 '갤러리 전체 감지', 'Work Agent', '자동 게시', 'AI 음악 생성 필수' 같은 과거 표현 수정.
3. **첫 구현 Phase 0~1을 실제로 시작**: 실행 가능한 Creator 최소 수직 흐름(업로드→편집 계획→무료 BGM/자막→렌더→미리보기→승인 상태)을 우선 구현.
4. 확인되지 않은 외부 API나 라이선스 때문에 전체 구현을 중단하지 말고, **명확하게 Mock으로 표시한 상태에서 로컬 제작 기능을 먼저 완성**.
5. 최종 사용자에게 코드를 단순히 나열하기보다 실행법·테스트 증거·현재 동작 범위·남은 할 일을 한국어 Markdown으로 보고.
