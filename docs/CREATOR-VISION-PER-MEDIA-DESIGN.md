# Creator 사진별 Vision 분리 설계안

상태: **JSON Creator 경로 구현 / Mock 검증, 실제 Vision 미검증** (2026-11-07). 아래 비교는 구현 전 설계 판단을 보존합니다. 기존 실호출에서 설명이 서로 바뀐 최초 지점은 원문 응답 부재로 미확정입니다. 이 변경은 의미적 정확성의 보장이 아닙니다.

## 현재 경로와 위험

`LocalRepositories.createPlan`은 프로젝트 `media_ids` 순서대로 소유권·원본 해시를 확인하고 최대 설정 개수(기본 5개)의 사진 축소본 또는 영상 프레임을 준비합니다. `CreatorAgent.createPlan`은 선택 미디어 ID 전체와 요청 문장, 시각 샘플을 **한 번** `LLMGateway.generate(vision_analysis)`에 전달합니다. `OpenAIProvider`는 각 `media_id` 라벨 바로 뒤에 이미지를 넣고, 한 응답에서 `media_insights`, `scenes`, `captions`를 받습니다. `CreatorAgent.normalizeVisionOutput`은 배열 위치 대신 ID로 연결하고, 누락·잘못된·중복 ID를 보류합니다. 유효한 ID에 잘못된 사진 설명이 붙으면 구조 검사만으로는 알아낼 수 없습니다. 자막은 `needs_review`, 장면 설명은 `ai_unverified`입니다.

| 방식 | 호출 수(N개 샘플) | 이점 | 남는 위험 |
| --- | --- | --- | --- |
| A. 현재 일괄 분석·기획 | 1회 | 빠르고 한 요청에서 전체 흐름을 계획; 현재 게이트·승인 흐름 재사용 | 여러 이미지와 긴 JSON에서 모델이 내용/ID를 혼동할 수 있음; 기획 출력 실패가 사진별 유효 분석도 가릴 수 있음 |
| B. 사진별 분석 후 통합 기획 | N회 Vision + 1회 텍스트 기획(제안) | Vision 요청당 이미지 하나; 서버가 응답 ID를 부여하여 응답 배열 재매핑을 없앰; 사진별 실패 격리 및 해시 기반 재사용 가능 | 모델이 **한 장의 사진도 잘못 설명할 수 있음**; 통합 기획에서 다른 사진의 사실을 섞을 수 있음; 호출·지연·비용 증가 |

## 제안하는 경계

1. 현재 프로젝트의 명시 선택 미디어만 후보로 삼습니다. 샘플 없는 미디어는 `unavailable`로 두고 내용을 추측하지 않습니다. 사진별 요청에는 이미지 샘플 **하나**와 최소한의 비민감 분석 지시만 넣습니다. 모델에게 `media_id`를 만들거나 복사하게 하지 않습니다.
2. 서버가 요청 전에 `media_id`, 소유자, 샘플 SHA-256, 콘텐츠 버전, 요청 ID를 묶습니다. 응답은 사진 내용 필드만 받으며, 서버가 그 요청의 `media_id`에만 귀속합니다. 실패·시간 초과·검증 실패는 해당 사진만 `needs_review`/`unavailable`로 두고 다른 사진의 설명을 복사하지 않습니다. 시간 초과는 자동 재시도하지 않습니다.
3. 승인된 선택 범위·목적·제공자와 **각 호출의 media_id**를 PrivacyGate가 다시 검사합니다. 현재 동의 검사는 프로젝트 ID 집합과 정확히 같은 집합을 요구하므로, 단일 ID 하위 호출을 허용하려면 동의 범위 검증을 안전하게 설계·테스트해야 합니다. 호출 수를 여러 task ID로 나눠 작업당 한도를 우회해서는 안 됩니다. 모든 호출은 상위 Creator 작업의 한도·예약액에 합산합니다.
4. 사진별 결과를 `observed_candidate`(모델의 관찰 후보), `uncertain`, `unavailable`로 구분합니다. 사용자 제공 사실은 별도 출처로 보관합니다. 통합 기획은 사진별 결과와 ID만 받아 장면 순서·시간·흐름을 만들고, 자막은 `observed_fact`/`user_information`/`emotional`/`narrative`로 분류하여 해당 `scene_id`·`media_id`에 묶습니다. 사진별 결과에 없는 구체적 사실을 다른 장면에 사용하면 보류합니다. 이 단계의 모델 근거도 실제 사진의 증명은 아니며 사용자 검토가 필요합니다.
5. 진단은 로컬에서 요청 ID, media_id, 샘플 SHA-256, 모델, 응답 상태·안전한 오류 코드, 매핑 결과, 콘텐츠 버전, 발생 시각만 보관하는 안을 검토합니다. 원본 사진·전송 바이트·프롬프트/응답 전문은 자동 영구 저장하지 않습니다. 샘플 해시는 민감한 파일 지문으로 취급하여 API/일반 로그에 노출하지 않습니다. 보관 기간과 접근 권한은 확정 전 제안으로 둡니다.
6. 분석 결과 재사용은 소유자·media_id·샘플 SHA-256·모델/분석 규격이 모두 일치할 때만 허용합니다. 계획 생성 실패가 기존 프로젝트를 변형하지 않게 사진별 분석은 별도 단계에서 보류하고, 기획 적용 시 현재 버전을 재검사합니다. 계획·자막 수정 시 현재 승인 무효화 규칙을 유지합니다.

## 비용·시간 경계

현재 Provider 예약식은 `설정된 이미지당 예약 단가 × min(샘플 수, 최대 이미지 수)`이며 기본 단가는 $0.01입니다. 예를 들어 사진 2장이면 기존 1회 요청에서 **예약 추정 $0.02**입니다. B의 Vision 2회도 이미지 예약액만 보면 $0.02이고, 별도 텍스트 기획 1회 예약액이 추가됩니다(기본식으로는 $0.01, 합계 예시 $0.03). 실제 공급자 청구액은 입력·출력 토큰과 이미지 처리량에 따라 다르며 이 값은 상한 보증이 아닙니다. 사진 5장에서는 기본 5회 한도에 맞춰 이미지 분석 5회 후 로컬 기획을 사용하며 여섯 번째 요청을 하지 않습니다. Vision 전용 제한 시간은 호출당 60초이므로 5장 순차 분석의 최악 대기 시간은 이미지 준비 시간을 더하면 300초를 넘을 수 있습니다. 실제 운영 HTTP 시간 경계는 아직 검증하지 않았습니다.

## 오프라인 검증과 미검증

- 기존 Mock 테스트: 정상/역순 응답의 ID 귀속, 잘못된·중복·누락 ID, 부분 유효 자막, 의미가 틀려도 유효 ID이면 `needs_review`로 남는 한계, 감성 자막의 검토 분류, 동의 없는 외부 호출 0회, Provider 실패·시간 초과 무재시도.
- **Mock 구현 검증**: 요청당 이미지 1개 강제, 서버 소유 ID 귀속, 한 사진 실패 격리, JSON 캐시, 다중 호출의 동의·예산 경계를 새 테스트에서 확인했습니다. **미검증**: 통합 기획의 의미적 사실 교차 차단, 실제 HTTP 시간 경계, 실제 사진의 의미 정확성.
- 이전 실호출의 교차 원인은 제공자 원문 응답이 없어 확정할 수 없습니다. B 구현 후에도 별도 사용자 동의하의 실제 사진·Vision·최종 MP4 검토 없이는 해결 완료로 표시하지 않습니다.

## 구현 시 영향 예상

`backend/src/agents/creator-agent.js`(분석/기획 분리·근거 연결), `backend/src/application/openai-provider.js`(사진 한 장 입력/응답 계약), `backend/src/application/llm-gateway.js`와 PrivacyGate/consent 검증(상위 작업 한도·하위 범위), `backend/src/adapters/filesystem/repositories.js`(사진별 상태·안전한 저장·버전), 관련 Mock/API 테스트, OpenAPI·API 가이드·Creator UI(사진별 실패/검토/예상 호출·비용 표시). PostgreSQL DB·마이그레이션·`scripts/`는 이 설계에서 변경하지 않습니다. 저장 구조와 API 계약 영향은 구현 전에 별도 검토합니다.

## 구현 메모

현재 JSON 경로는 기존 전체 프로젝트 미디어 ID와 일치하는 동의를 먼저 요구하고, 각 사진 요청에서 그 ID 하나에 대해 PrivacyGate를 다시 검사합니다. 모든 호출은 같은 Creator `task_id`의 비용·횟수에 합산합니다. 모델 출력의 `media_id`는 귀속 근거로 사용하지 않으며 다른 ID를 반환하면 그 사진은 실패로 둡니다. 사진별 성공 결과만 `creatorVisionInsights`에 보관합니다. 전체 기획 단계는 이미지 없이 사진별 분석 후보와 사용자의 요청을 보내며, 호출 여유가 없으면 로컬에서 장면과 검토 대상 자막을 만듭니다. **모델이 한 장의 사진을 잘못 설명하는 위험과 전체 스토리의 사실 오류는 남습니다.** 원본 응답 전문·전송 이미지 바이트는 보관하지 않습니다. 기존 사용자 프로젝트의 옛 기획/자막을 자동 변경하지 않습니다.
