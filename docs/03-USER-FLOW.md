> 상태: 설계 초안 v0.2 · 수정일: 2026-10-30 · 대상: 1인 개인용, 향후 다중 사용자 확장  
> 원칙: **존댓말 응답 / 크리에이터 상업적 수익화 / 권리 검증 / 사용자 통제 / 로컬 우선**  
> 표기: **[확정]** 합의된 목표 · **[제안]** 구현 선택 · **[검증 필요]** 정책·환경 확인 전 결정 보류

## 흐름 A — 직접 쇼츠 제작
1. 사용자가 앱에서 콘텐츠 제작을 선택하거나 예투에게 요청합니다.
2. 휴대폰 갤러리에서 사진/영상을 선택합니다(권한 거부 시 파일 선택으로 대체).
3. 앱에서 파일 수·크기·형식 검사 후 업로드 작업 ID를 생성합니다.
4. Creator가 미디어 분석 → 컷 후보 → 자막 원고 → 배경음악 후보를 제시합니다.
5. 사용자가 스타일·길이·음악을 수정/승인합니다.
6. Worker가 렌더링하고 자막 잘림·오디오·영상 규격을 점검합니다.
7. 저작권 게이트 결과와 영상 미리보기를 표시합니다.
8. 사용자가 **게시 대상/가시성**을 확인해 승인합니다.
9. Publisher가 공식 API를 호출하고 성공 상태·게시 URL 또는 실패를 기록합니다.

## 흐름 B — 선택 업로드 완료 후 제작 제안 [확정]
1. 사용자가 Android Photo Picker로 원하는 사진·영상만 선택합니다. 미선택 갤러리는 열람하거나 감지하지 않습니다.
2. 선택 파일만 인증된 PC FastAPI로 업로드하고 서버가 파일·manifest 무결성 및 완료 이벤트를 검증합니다.
3. `user_id + manifest_hash`에 대해 제안 1회만 생성하며 알림/앱 화면에 “선택하신 사진·영상으로 쇼츠를 만들어 드릴까요?”를 표시합니다.
4. `제작하기` → 기획 컨펌 / `나중에` → 보류 / `취소` → 해당 제안 종료.
5. PC가 꺼져 있으면 대기 상태를 표시하고 안전하게 재연결하며 중복 업로드·제안하지 않습니다.
6. 위치·EXIF가 있더라도 사용자가 선택한 파일 범위에서만 사용하고 필요 없는 외부 전송을 금지합니다.

## 흐름 C — 편집 수정
- “음악을 더 잔잔하게요” → 기존 프로젝트 복제 → 음악 교체 → 권리 재검사 → 새 렌더 버전 → 재승인.
- 승인 이후 파일이 수정되면 이전 승인은 자동 무효화됩니다.

## 흐름 D — 예외
| 상황 | 사용자 경험 |
|---|---|
| 갤러리 접근 거부 | 직접 파일 선택 안내 |
| PC 오프라인 | `대기 중` 표시, 전송 재개 |
| 렌더 실패 | 오류 메시지·재시도, 원본 유지 |
| 음악 라이선스 미확인 | 게시 차단, 승인된 다른 음악 추천 |
| SNS 인증 만료 | 재로그인 안내, 자동 재게시 금지 |
| 플랫폼 비허용 | 다운로드/공식 앱 공유 대안 제공 |

## v0.2 대표 사용자 흐름
### 콘텐츠(모바일 중심)
1. 앱 콘텐츠 화면 → 사진·영상 선택(Photo Picker) → 확인 → PC 서버로 안전하게 업로드.
2. 업로드 완료 후 프로젝트 폴더/작업 ID 생성 → 예투의 제작 제안.
3. 제작 수락 → 기획안(길이·스타일·컷 순서) 확인/수정/승인.
4. 자막·음악 초안 확인 → 텍스트 또는 STT로 수정 요청 → 중간 승인.
5. 렌더링 결과 미리보기 → 수정 반복 → 권리 검사 및 플랫폼/공개범위 확인.
6. **최종 승인한 버전만** 게시. 실패·부분 성공은 플랫폼별 기록.
### 일기
1. 일기 선택 또는 예투에게 텍스트·음성으로 요청.
2. 오늘 일정(실행 여부 확인), 기분·건강 기록 중 참조할 정보를 확인.
3. 구조화 개요 확인/수정 → 일기 초안 확인/수정(음성·텍스트).
4. 최종본 확인 후 승인 → 정식 일기 저장. 승인 전은 초안 상태로만 보관.
