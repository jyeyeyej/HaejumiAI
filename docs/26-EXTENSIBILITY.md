# 26 — 해주미 확장형 Agent·기능 설계 (v0.3.2)

> 상태: 확장성 요구 [확정], 구체적 플러그인 인터페이스/분리 시점 [제안]. 현재 v0.3 Creator 우선 및 전문 Agent 4개 확정을 바꾸지 않음.

## 1. 목표
해주미는 초기에는 Creator, Schedule, Wellness, Diary 네 Agent로 시작하지만, 이후 블로그 글 작성·발행이나 음악 작곡·편집, 다른 개인비서 서비스를 모듈 형태로 확장할 수 있어야 한다. 새 기능을 추가할 때 Supervisor 전체를 다시 작성하거나 기존 Agent에 무분별하게 기능을 끼워 넣지 않는다.

## 2. 변하지 않는 코어
- Supervisor(예투): 의도 라우팅, 허용된 기능 검색, 작업/상태/승인 흐름, 비용·개인정보 정책 게이트.
- 공통 서비스: 인증, 사용자별 접근 제어, 승인 버전·해시 검증, 영속 작업 상태, 파일/메모리 저장, 감사 기록(민감 원문 제외), LLM Gateway/Budget Guard.
- 외부 시스템 연결은 Tool/Connector 계층에서만 처리; Agent에 API 토큰·무제한 네트워크 권한 직접 제공 금지.

## 3. 모듈 등록 계약 — 제안
각 모듈은 고유 `module_id`, `version`, `capabilities`, 입력/출력 Pydantic 스키마, 허용 `tools`, 데이터 접근 `scopes`, 외부 전송 목적지, 승인 단계, 비용 제한, 오류/재시도 정책, 테스트 참조를 선언한다.
Supervisor는 Registry에서 기능을 찾아 사전 허용된 모듈에만 작업을 전달한다. 미등록 기능 요청은 무작정 Tool 호출하지 않고 지원 불가·추가 설정 필요로 응답한다.

## 4. 확장 후보 (MVP 후순위)
| 후보 | 최초 권장 형태 | 핵심 흐름 | 출시 전 검증 |
|---|---|---|---|
| 블로그 | Creator의 `blog` 모듈 또는 독립 Blog Agent(추후 결정) | 주제·자료 선택 → 글 초안 → 사실·저작권/사진 검토 → 수정 → 블로그 계정/공개범위 최종 승인 → 공식 API가 허용하는 방식으로 발행 | 블로그 서비스별 공식 API, 계정 권한, 출처, 개인정보·광고 표시 |
| AI 음악 | Creator의 `music` 모듈 또는 독립 Music Agent(추후 결정) | 기획 → 로컬/허가 모델로 작곡·편집 → 미리듣기 → 라이선스 확인 → 사용자 승인 → 저장/활용 | 모델 가중치·출력물 상업권·플랫폼별 사용권, PC 자원 및 비용 |
| 기타 후속 | 상황별 모듈/Agent | 계획 → 초안 → 검토 → 명시적 승인 → 실행 | 데이터 접근·비용·안전·서비스 약관 |

## 5. 확장 시 보안·승인 경계
- 개인 일정·일기·건강 데이터를 블로그·음악 모듈에 기본 제공하지 않음. 필요 시 목적별 사용자 동의 및 최소 범위로 접근.
- 외부 LLM, 블로그 플랫폼, 음악 API 등으로 데이터를 보낼 때에는 전송 데이터·목적지·목적을 표시하고 명시적 동의 및 서버 정책 검증 필요. 동의 없으면 차단/로컬 대안 제공.
- 블로그 발행과 SNS 게시 모두 **각 게시물별 최종 승인** 필요. 중간 컨펌/과거 승인/음성 인식 명령만으로 외부 게시 금지.
- 승인 대상은 `task_id`, `checkpoint_id`, 결과 `version/hash`, 계정, 플랫폼, 공개범위에 결합; 변경하면 승인 무효화.
- 개별 모듈은 제한된 파일 경로·계정 scope·Tool allowlist만 사용한다. 비밀키는 Backend 전용.

## 6. 개발 방식과 품질 게이트
1. 요구사항을 `[확정]/[제안]/[검증 필요]/[후순위]`로 분류하고 DECISIONS에 기록한다.
2. 모듈의 독립 계약/테스트와 기존 Creator의 회귀 테스트를 모두 작성한다.
3. Mock→로컬 테스트→권한·외부 전송·비용 테스트→사용자 승인→실연동 순서로 단계화한다.
4. 실패하거나 미인증인 게시 기능은 임시 파일 저장/내보내기만 제공하고 게시 성공이라 표시하지 않는다.

## 7. 수용 테스트 — 추후 확장 구현 시 필수
- 새 모듈 등록/해제가 기존 네 Agent 동작 및 요청 라우팅을 깨뜨리지 않는다.
- 미등록 도구, 모듈 간 Wellness/Diary 무단 열람, 미승인 외부 LLM 전송을 거부한다.
- 블로그 임시 원고는 발행 전 외부 전송되지 않으며, 결과 수정 시 게시 승인이 무효화된다.
- 음악의 상업 사용권이 불명확하면 영상 삽입/수익화 게시가 차단된다.
- 모듈 비용은 작업/모듈별로 측정되며 예산 초과 시 클라우드 호출이 차단된다.

## 8. 구현 시점
MVP Creator와 공통 승인·보안·비용 게이트는 우선 구현. Registry의 최소 인터페이스 및 모듈 경계만 초기에 설계하고, 블로그·AI 음악 생성 기능 자체는 MVP 범위에 포함시키지 않는다.
